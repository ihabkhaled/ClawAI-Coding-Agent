## Implemented

- Added strict, provider-neutral Runtime Protocol V2 schemas and semantic
  capability-manifest validation.
- Added the sole canonical runtime-event reducer owned by extension state.
- Added truthful local, WSL, SSH, Dev Container, Codespaces, web-limited,
  virtual, empty, multi-root, unknown, and untrusted target mapping from
  injected host facts.
- Added authenticated backend protocol negotiation after profile validation.
- Preserved deterministic `legacy-v1` fallback for endpoint absence,
  incompatibility, timeout, malformed data, or missing foundation features.
- Preserved refresh-token handling, cancellation, account/backend boundaries,
  Workspace Trust, path containment, secret denial, and the existing reviewed
  edit-plan path.
- Kept tool execution, PTYs, shell execution, elevation, and native helpers out
  of 0.18.0.

## Architecture and contracts

- Pure runtime contracts, negotiation, capability construction, and event
  reduction live outside VS Code-specific code.
- The VS Code adapter receives serializable host facts and does not execute
  discovery commands.
- `ExtensionState` remains the single runtime state owner.
- `BackendClient.getRuntimeProtocol()` uses the existing authenticated agent
  namespace. The extension selects V2 only when the required version,
  transport, and inert foundation features overlap.
- Capability discovery is descriptive and never grants permission.
- Runtime payload validation rejects hidden-reasoning fields for known event
  types. Unknown future event types remain timeline-only and cannot change
  derived state.

## Security, permissions, and migration

- No database migration, RabbitMQ event, new microservice, native executable,
  PTY, command executor, or elevation path is introduced by the extension
  release.
- The capability manifest does not grant authorization and does not expose the
  detected shell path in its serialized target.
- Known runtime events do not accept hidden chain-of-thought fields; only
  concise, deliberately user-visible summaries may be represented.
- Protocol absence or incompatibility degrades to V1 without disabling the
  existing security boundaries.
- This is an additive protocol migration. Runtime tool execution remains a
  separately gated 0.19.0 concern.
