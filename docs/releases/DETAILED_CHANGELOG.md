# Detailed changelog

This is the full engineering log for ClawAI Coding Agent: every release with its internal notes, decisions and verification detail. The short, user-facing release notes are in [CHANGELOG.md](../../CHANGELOG.md).

## 1.98.0

Long runs survive the 15 minute access token. New `src/headless/token-session.ts` keeps the access and refresh token of a run (taken from the sign-in exchange, or from `CLAW_TOKEN` plus `CLAW_REFRESH_TOKEN` / `auth.refreshToken`), rotates through `POST /auth/refresh` at 80% of the token life (read from `exp`, 10 minutes when unreadable) and before any request that would start inside the last minute (capped at 20% of the life), single-flight so concurrent callers share one rotation, replacing both tokens in one assignment because the backend burns a refresh token on first use. `HeadlessTransport` asks the session for the live token on every call, renews once and resends the same bytes on a 401, and `readRuntimeEvents` now opens each connection with the live token, cuts it deliberately after a rotation and reconnects at once from the last sequence seen (the cursor already carried across reconnects; this is now covered by a test). A refused refresh is final (no second try, which the backend would read as a replay), ends as a 401 that names the reason (exit 3), and for email and password falls through to the existing re-login continuation; no error or event carries a token. The extension already rotates in `BackendClient.ensureFreshSession` (2 minute skew, single flight in `SessionRefresher`) and resumes its stream with the cursor, so it only shares `accessTokenExpiresAt` and nothing was duplicated. Live: login, refresh (new access and refresh token, both usable) and a garbage refresh (401) were observed against https://claw.local; a real 20 minute run and a model round were not run (provider out of credit).

Docs and tests that make the 1.96.0 toolset usable. `docs/TOOLS.md` is generated by `npm run docs:tools` (`scripts/generate-tools-doc.mjs` runs `tests/unit/tools-doc.test.ts` with `UPDATE_TOOLS_DOC=1`, like the permission matrix): operations, grants, per-mode approval cells, argument tables and definition sizes come from the real tool definitions and `needsApproval` / `policyOutcome`, while purposes, limits, failure messages and examples are written in `tests/unit/tools-doc-notes-*.ts` and checked (the operation lists must equal the real ones, every quoted failure message must still exist in `src/`, every CLI example must parse with `parseHeadlessArgs`, every SDK example must build an agent). `tests/unit/headless-doc.test.ts` keeps one Flags row per parser flag, the exit-code and Events tables complete and the code fences closed (HEADLESS.md had a stray table row at the top, an unclosed four-backtick fence around the Browser example, and no rows for `images.not-delivered`, `context.collected` or the `plan-incomplete` continuation reason; its per-tool identifier table now points at TOOLS.md). `tests/unit/docs-index.test.ts` checks that each skill is reachable from CLAUDE.md and AGENTS.md and that every `clawai` command and `--plan-file` JSON in the new docs and skills parses. New skills: `deliver-a-flagship-with-the-agent`, `test-a-ui-with-the-browser-tool`, `test-an-api-with-http-request`, `run-long-commands-with-process-watch`, `orchestrate-parallel-agents`, `write-a-plan-file`; new `docs/FAQ-AGENT-TOOLS.md` and a README section on turning the capabilities on safely. Found, not changed: the `--help` text says `--permission-mode` grants "all" tools (it grants the original six) and that `--browser-allow-host` "needs `--allow-tools browser`" (it adds the grant itself), and the events schema has no entry for `images.not-delivered` or `context.collected`.

Packaging audit after the 1.96 tools: 1.95.0 to 1.97.0 grew the VSIX from 6.83 MB to 6.86 MB because `playwright-core` was already a separate lazily required `dist/playwright-runtime.js` (7.2 MB, never parsed at activation) and the new tools added only source. `http.request` loaded `node:http` and `node:https` at import time, which makes Node load its bundled fetch client (undici) for every SDK and headless start; they now load on the first request. The SDK entry now exports the types its options reach (`ShellOptions`, `RetryTuning`, `StuckInfo`, the MCP server config types, the vision and web-research input types, `HeadlessRunRequest`, `AgentMemoryMode`), enforced by `tests/unit/sdk-types-surface.test.ts`; `tests/unit/sdk-lazy-imports.test.ts` fails when the browser library, `node:http` or undici becomes an eager import; `tests/unit/runtime-licenses.test.ts` fails on a copyleft-only runtime dependency; `package:audit` now rejects any stray root file, test, fixture, screenshot, worktree or source-map path in the VSIX and `vitest.live.config.ts` is excluded from it.

## 1.99.0

Adversarial QA of `browser.page` and `http.request` (85 scripted rounds through dist/sdk.mjs against local attacker pages, redirectors and raw sockets) found six browser defects and no http.request breach. Browser: a page WebSocket or Worker reached private hosts because Playwright's request routing never sees them; a public-looking name that resolves to loopback (`localtest.me`, `nip.io`) and `localhost.` with a trailing dot passed the name-only check; one page stuck in `while(true){}` hung the whole call forever; a password field's value showed in snapshots. Fix at the root: Chromium now runs behind a local egress proxy (`browser-egress-proxy.ts`, `browser-egress-policy.ts`) that resolves each name itself, refuses private answers unless the host is listed, and dials the address it judged; every call has a hard ceiling that closes the browser (`browser-call-deadline.ts`); snapshots hide password values. `classifyAddress` now sees IPv4 inside IPv6 (compatible, NAT64, 6to4), site-local and 198.18.0.0/15. A `host:443` allow entry now matches a default-port URL. Tests: `browser-egress-*`, `browser-address-hardening`, `browser-adversarial` (real Chromium), `browser-injection-pipeline`, `http-tool-adversarial`.

Adversarial pass over `workspace.shell`, `process.watch` and `code.gates` (about 160 rounds through `dist/sdk.mjs` with scripted tool calls). Fixed: `process.watch` `untilMatch` could freeze the host for good on a backtracking pattern such as `(a|aa)+$` (HIGH; the nested-repeat check missed it; lines are now tested in a `vm` context with a 100 ms limit and a slow pattern is dropped); `code.gates` `files` such as `a/../--fix` became tool flags once normalised, and a flaky re-run took file names from the runner's own output (MEDIUM; both now refuse or prefix `./`); the approval callback got the live arguments object, so it could change what ran after approval (MEDIUM; it now gets a deep copy); operator `--shell-deny` patterns were tested only against the unquoted text, and a backtracking one froze the host on a long script (MEDIUM; both forms are tested now, in a 200 ms vm limit, and a pattern that overruns refuses the script); the screen missed `bash -c "$(curl ...)"`, cmd caret escapes and `cmd /c set` (MEDIUM, best effort); a NUL in a script failed after approval with the raw script in the error (LOW); log files used the model's name, so `CON` or `nul` were Windows devices (LOW; files are now `<n>-<name>`); a pass whose output lists failures now carries a note. Not fixed, documented: background jobs of a normally finished script outlive it.

Adversarial QA of agent.team, knowledge.context, vision.describe and task.plan (78 scripted rounds through the real agent pipeline), nine defects fixed with regression tests. agent.team: a child worktree patch is now audited (no renames, symbolic links, gitlinks or odd modes; git is run with --no-renames, so a rename can no longer delete a path outside the child scope), a child calls now come out of the parent allowance (the parent run guard counts calls held by children, and a parent keeps 4 calls in reserve), and checkouts left by a killed run are swept after 3 days. knowledge.context: .gitignore matching is now a linear-time automaton (a pattern like *a*a*a*b hung the walk), secrets split by zero-width characters are redacted after the hidden characters are removed, invisible Unicode tag characters, variation selectors and C1 controls are stripped, the preamble tag removal cannot be reassembled by markup removal, and the preamble reads at most 256 KiB of a root file and refuses a link that leaves the workspace. vision.describe: metadata is removed even when a file has trailing data (PNG after IEND, JPEG after EOI), WebP EXIF and XMP chunks are removed, a header declaring more than 20000 pixels a side or 100 million in all is refused, the uploaded file name is neutral, a name like id_rsa.png is screened as id_rsa, and the same picture and question is answered from memory. task.plan: titles and notes are one line without hidden characters (no forged steps), a plan file over 128 KiB on disk is ignored, and the executable allowlist no longer treats node.js or node.exe;calc as node (only .exe and .cmd are ignored). Not run live: both live models answered out of credit.

Permission behaviour of the newer tools is now one table (`src/sdk/tool-permission-table.constants.ts`, a row per tool operation with a decision per mode) that `needsApproval` and `permissionsForMode` enforce, that `tests/unit/new-tools-permission-matrix.test.ts` pins in all five modes, that `tool-permission-editor-agreement.test.ts` runs through the editor's `evaluatePolicyV2` and the real runtime adapter, that `tool-permission-drift.test.ts` fails when a tool operation has no row, and that `docs/PERMISSION_MATRIX.md` is generated from. The editor's classification table gained `browser.page`, `http.request`, `task.plan`, `knowledge.context`, `vision.describe`, `workspace.shell` and `agent.team` (before, the editor treated them as unclassified R3 and denied them in Plan). Fixed: `browser.page click|type|press` ran unasked in `autonomous-scoped` (now R3 network-write, asked in every mode); `agent.team spawn` ran unasked in `accept-edits` while the editor's Auto Edit asks (now asked); `vision.describe` is asked in `strict` (images cannot be redacted); an unknown browser, agents or shell operation is asked about instead of run. Removed the duplicate rules `browser-tool-policy.ts`, `COMMAND_TOOL_OBSERVATIONS` and `BROWSER_ACTING_OPERATIONS`.

`clawai orchestrate --plan plan.json` and SDK `orchestrate(plan)`: a deterministic orchestrator on top of the `agent.team` spawn path (src/sdk/orchestrate-_.ts, src/headless/orchestrate-_.ts). A zod-validated plan (JSON schema in schemas/) describes stages as a DAG with up to `maxParallel` narrowed agents at once, per-agent scope, budget, done checks, model pools, isolation, and per-agent `http.allowHosts`, `browser.allowHosts` and `shell` (spawn narrowing in agent-team-narrow.ts: hosts must lie inside the parent's, the shell needs both switches and stays approver-gated); stage gates run orchestrator-owned checks; `onFailure` stops, continues or retries; overlapping write scopes between agents that can run together are refused at validation; cancel and timeout cancel every agent and remove worktrees; reports go to `<state>/orchestrate/<run>/report.json` and `report.md`; `--dry-run` prints the DAG. Live rounds: NOT RUN (the model providers answered out of credit); see docs/ORCHESTRATION.md.

Editor wiring for two of the 1.96.0 tools, both off by default. `http.request` (operations `get` and `send`, so the policy can tell a read from a write) and `workspace.shell` are advertised in the capability manifest only while the USER-scope settings `clawAI.tools.httpAllowHosts` (non-empty) and `clawAI.tools.shellEnabled` (true) say so, and each executor re-reads its setting on every call; a workspace setting cannot grant either (machine scope plus an `inspect().globalValue` read, the same rule as the command sandbox). `workspace.shell` is classified as an irreversible local mutation, which every mode asks about, and its script is the policy subject command so project and organization rules match it. The generic approval card showed only the effect class and `target:workspace`; `describeRuntimeEffect` now shows the action, the host and the exact command, script or method and URL (secrets redacted, cut at 4,000 characters), for every tool. The live lane gained three env-selectable scenarios (`CLAW_LIVE_SCENARIO=server-browser|plan-gates|approval-cards`) that write their own user settings, save every approval card and a screenshot of each tool card, and record PASS/FAIL checks. Not wired, and why: see `docs/LIVE_TOOL_SCENARIOS.md`. Tests: `opt-in-tools-editor`, `live-tool-scenarios`.

Dogfood fix (ClawBoard, scripted transport, no real model): `http.request` refused `127.0.0.1:4310` with only "Allowed: 127.0.0.1", which hides that a rule without a port means ports 80 and 443; the refusal now says so and names the `--http-allow-host host:port` to add (or the one port a pinned rule allows).

Tool catalog cost (P2-06): the definitions the model is sent every turn were slimmed (descriptions tightened, schema descriptions and numeric bounds dropped where the tool already enforces them), cutting the default catalog from 5,274 to 4,004 characters, default plus command from 9,723 to 7,337 and every category from 21,396 to 15,889 (the nine newer tools -25%, the older four -27%); `npm run tools:size` and `tests/unit/tool-catalog-size.test.ts` hold per-tool budgets. New `--tools-profile minimal|dev|full|<patterns>` narrows the offered tools (never grants), and `--defer-tools` / `deferTools` sends rarely used tools as hashed stubs loaded through `runtime.tool_search` and `POST chat-messages/runtime/runs/:runId/tools`, which the live backend accepted (stub start, matching load, tampered and undeclared loads refused with 409); the end-to-end model rounds were NOT RUN because the Ollama connector answered out of credit twice.

Integration of the wave-2 branches: one source-of-truth permission table for every new tool operation (browser click/type/press and agent spawn now asked in every mode; vision asked in strict; unknown operations asked), the adversarial rounds on the browser (egress proxy that judges every connection incl. WebSockets and names resolving to loopback; per-call deadline; password values hidden), http.request, shell, process.watch, code.gates, agent.team (rename-based scope escape closed; budget double-spend closed), knowledge.context, vision.describe and task.plan, tool-definition size cuts (-25%), `--tools-profile`, `--defer-tools`, the `orchestrate` plan runner, opt-in editor settings `clawAI.tools.httpAllowHosts|shellEnabled|shellDeny`, and small defects from the flagship dogfood: a refused commit now returns `ok:false` with a plain reason, git output has no terminal colour codes, a stopped process no longer reports the kill's exit code, and a bare host allow rule now explains that it allows only ports 80 and 443.
