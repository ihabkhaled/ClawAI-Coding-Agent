# Coding agent delivery rules

These rules supplement `AGENTS.md` and `CLAUDE.md`. Each says where it is enforced.

## Delivery

1. A command, setting, view, tool or service is delivered only when a reachable call path and an appropriate test demonstrate it. Dormant code is not a feature. Enforced by: `npm run inventory:verify` (computed call path per surface row), review.
2. Retry only tagged transport or temporary state-store conditions from the latest event cursor. Never retry terminal, permission, tool, validation, budget or unsafe-operation outcomes as transport failures.
3. Live coding must independently execute the produced artifact. Model narration and tool counts are not completion evidence. Enforced by: `npm run check:live`, `skills/run-live-rounds/SKILL.md`.
4. Browser callback pages may not promise that an externally opened browser tab will close. They remove OAuth data from the visible URL, keep a nonce CSP, and give an honest return/close action without arbitrary deep-link payloads. A loopback callback that may run in a remote extension host must be passed through `vscode.env.asExternalUri` before it is registered with an authorization server; never expose the remote host's raw loopback URI to the user's browser.
5. Each delivery release advances the second SemVer component (`1.47.0`, `1.100.0`, `1.101.0`); patch releases advance the third. Source, lockfile, changelog, VSIX manifest, installed extension and release asset must agree. Enforced by: `npm run package:audit`, `npm run lab:release-parity`, `skills/land-a-release/SKILL.md`.
6. Every main-bound change is a delivery release and advances the second SemVer component exactly once (`1.90.0 -> 1.91.0`), resetting patch to zero. The pre-commit hook prepares the bump; CI verifies it independently. Source, lockfile, changelog, README and final VSIX must agree. Enforced by: `.githooks/pre-commit`, `scripts/verify-version-bump.mjs`, `npm run package:audit`, and `skills/land-a-release/SKILL.md`.
7. Maintain an explicit inventory of commands, settings, options, views, buttons, tool APIs, research and crawl flows. Every row records PASS, FAIL, BLOCKED or NOT RUN and evidence. Generated by `npm run inventory:surface` into `docs/parity/SURFACE_INVENTORY.md`; never hand-edit rows.

## Code rules enforced by tooling

7. ESLint (`eslint.config.mjs`, `--max-warnings=0`): `strictTypeChecked` + `stylisticTypeChecked`; `no-explicit-any`, `no-non-null-assertion`, `no-console`, `consistent-type-imports`, `import/no-cycle`, alphabetised `import/order`; `complexity` <= 12; `max-lines` <= 500 (blank lines and comments skipped). Unused args must start with `_`. No `eslint-disable` or `@ts-ignore`.
8. TypeScript is strict (`npm run typecheck`, `tsc --noEmit`). Declarations (types, interfaces, enums, module constants) live in `*.types.ts` / `*.constants.ts`, not inside logic files (convention, reviewed).
9. Layering: `src/core` is pure (no `vscode`); `vscode` is wrapped in `src/infrastructure`; only `src/backend` performs HTTP; services depend on ports. Settings are read only through `ConfigurationService`.
10. Coverage: 85% branches/functions/lines/statements (`vitest.config.ts`). `npm run coverage:scope` fails when a named critical file or anything in `src/core/runtime/` is missing from coverage; it reads git-tracked files, so stage new files first.
11. Localization: every user-facing string goes through `vscode.l10n.t` or `package.nls.json`, translated for all 12 locales (ar de es fa fr hi it ja pt ru th zh). Enforced by: `npm run l10n:verify` (regenerate + git diff), `tests/unit/localization-coverage.test.ts` (no new English fallbacks; `l10n/untranslated-baseline.json` may only shrink).
12. `npm run scan:paths` rejects machine-local absolute paths (user home, temp) in `src`, `tests`, `media`, `scripts`. `tests/unit/source-control-bytes.test.ts` rejects raw control bytes.
13. `npm run package:audit` asserts, among others: valid SemVer, lockfile and changelog match, every contributed command is registered in a file calling `registerCommand`, all locale files exist, no VSIX at repo root (artifacts go in `builds/`), CI and release workflow invariants. Runtime dependencies pass `npm audit --omit=dev --audit-level=high`.

14. Nothing reaches `main` without a fresh delivery minor and green GitHub gates. CI splits version, quality, unit/coverage, extension-host, Playwright and dependency-audit lanes; VSIX packaging runs only after all of them pass. A successful main CI run triggers Release, which must create the GitHub Release and publish the same final VSIX to the VS Code Marketplace. Reusing an existing tag or skipping Marketplace publication is a failure. Enforced by: `.github/workflows/ci.yml`, `.github/workflows/release.yml`, `scripts/verify-version-bump.mjs`, and the shipping skills.

## Security

14. Never store or log passwords, tokens, cookies, prompts or unredacted backend errors (`src/core/redaction.ts`). No secret-bearing settings.
15. Workspace content is untrusted and bounded; secrets are always denied; every modifying workflow stages a reviewable diff, rechecks Workspace Trust, and applies one atomic edit. Never weaken path validation or permission-mode approval.
16. Webviews: strict CSP with fresh nonces, no `innerHTML` for model/backend/user data, validated inbound messages. Backend responses are zod-validated.

## Enforcement

Use `skills/verify-coding-agent-readiness/SKILL.md`, installed-host tests, runtime-resume tests, Playwright suites, package audit, release-parity checks and the release workflow. Update this file and the readiness pack when a repeatable constraint is discovered.
