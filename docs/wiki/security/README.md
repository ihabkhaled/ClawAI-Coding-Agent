## Security model in short (current)

- The backend is authoritative for identity, entitlement, routing, inference and provider keys. The extension is authoritative for local capability truth, approvals, execution, cancellation and evidence ([threat model](../../THREAT_MODEL_RUNTIME_V2.md)).
- Nothing an outside party supplies can widen access. Policy fields only narrow, and an organization policy is a ceiling no mode exceeds ([ADR 0003](../../adr/0003-permission-modes-under-an-organization-ceiling.md)).
- An untrusted workspace is denied for every operation in every mode ([permission matrix](../../PERMISSION_MATRIX.md)).
- Release blockers are named in the threat model: critical or high vulnerabilities, RCE, path escape, authorization bypass, stale-state races, secret leakage, data loss, replayed effects.

## Trust boundaries (current)

| Boundary              | What crosses it                                           | Where the rule lives                                                                                                                                                                                                             |
| --------------------- | --------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Backend               | Sign-in, chat, run events, entitlement, org policy        | Runtime-validated responses, redacted bounded errors, HTTPS off loopback ([docs/SECURITY.md](../../SECURITY.md), "Backend compromise or drift")                                                                                  |
| Workspace             | Files, git state, `.clawai` config, repo-supplied plugins | Workspace Trust, path validation, built-in secret exclusions, atomic apply ([docs/SECURITY.md](../../SECURITY.md), [rule 15](../../RULES.md))                                                                                    |
| Model output          | Edit plans, command plans, tool calls                     | Treated as untrusted until strict local validation, the active permission mode and approval allow it ([threat model](../../THREAT_MODEL_RUNTIME_V2.md))                                                                          |
| Webview               | Messages in, rendered text out                            | Validated message union, strict CSP with a nonce, no `innerHTML` for untrusted data ([rule 16](../../RULES.md))                                                                                                                  |
| MCP servers           | Config, tool calls, tool results, OAuth tokens            | Stdio only in a trusted workspace, every call asks, tokens in `SecretStorage` ([ADR 0002](../../adr/0002-mcp-oauth-uses-the-loopback-callback.md), threat model)                                                                 |
| Plugins, marketplaces | Archives, catalogs, hooks, git clones                     | Workspace plugins off by default, sha256 pins, publisher signatures, hooks approved by digest ([ADR 0006](../../adr/0006-plugin-publisher-signatures.md), [ADR 0007](../../adr/0007-secure-by-default-plugins-hooks-network.md)) |
| Shell and commands    | Command text, arguments, environment                      | Executable plus argument arrays, no shell text, environment allowlist, optional sandbox that is off by default ([sandbox page](../features/sandbox-redaction-secrets.md))                                                        |
| Browser               | Pages, clicks, typing, downloads, screenshots             | Isolated contexts, origin policy, private addresses refused, click, type and press never run without asking ([threat model](../../THREAT_MODEL_RUNTIME_V2.md), matrix)                                                           |
| Network egress        | HTTP tool, web research, plugin and MCP fetches, OTLP     | Private addresses refused, https only off localhost, telemetry opt-in, publishing scrubbed twice and blocked under zero retention ([threat model](../../THREAT_MODEL_RUNTIME_V2.md))                                             |

Two permission flows exist. The older edit-proposal flow still asks before commands. In Runtime V2 Full mode, `workspace.command.run` runs without asking, and `workspace.shell.run` never runs without asking. The matrix explains the difference.

## Planned: Wolverine controls (planned, nothing built)

Wolverine is the planned loop from opt-in failure reports to tested fixes and releases. Sources are in the ClawAI monorepo and are not linked here, because this repository builds alone: `docs/13-adr/adr-229-wolverine-planes-and-incident-intake.md` and `docs/03-architecture/agent-incident-threat-model.md`. The threat model is a draft for batch B1 (2026-11-28) and ADR-229 is "accepted in part".

- Four planes with no shared credentials: interactive, diagnostics, remediation, release control.
- Intake in its own service with its own database, no outbound calls except token checks, no new dependency without owner review.
- A per-installation Ed25519 key kept in `SecretStorage`; every batch is signed, with freshness and one-time nonces.
- Budgets that fail closed on a Redis error; a per-address nginx limit zone.
- Server-side redaction and quarantine before storage; reports are untrusted data and never start a job.
- A healer on a separate machine with no production secrets; branch and pull-request identity only, through a broker.
- Kill switches as database config, off by default, each with an on and an off test.
- Invariants for the owner: protected change classes always need the owner, the healer never merges its own pull request, automatic release stays off.
- Extension side (B5): consent, a bounded local queue, signing, and a user view with delete.
